작업 방식

혼자 만든 프로젝트도 팀에서 일하듯 관리했습니다.

커밋 메시지에는 무엇을 왜 바꿨는지 한 줄로 적습니다. 브랜치는 기능 단위로 나누고, 머지 전에 직접 한 번 리뷰합니다.

README에는 실행 방법과 화면 캡처를 넣어서 다른 사람이 클론한 뒤 3분 안에 실행할 수 있게 합니다.

해결한 문제

프로젝트를 하면서 해결하는 데 오래 걸린 문제 일곱 가지입니다.

  1. useState 일곱 개로 늘어난 상태문제: 견적 조건이 늘 때마다 useState가 하나씩 늘어 일곱 개가 됐고, 하나를 바꾸면 다른 값이 어긋났습니다. 해결: 함께 바뀌는 값끼리 묶어 useReducer 하나로 합쳤습니다. 결과: 조건을 추가할 때 액션 한 줄만 쓰면 되고, 값이 어긋나던 버그도 없어졌습니다.
  2. 두 기기에서 고친 기록이 사라짐문제: 같은 책 기록을 휴대폰과 노트북에서 고치면 나중에 고친 쪽이 앞의 기록을 통째로 덮었습니다. 해결: 필드마다 마지막 수정 시각을 저장해 비교했습니다. 결과: 서로 다른 필드를 고친 경우 두 수정이 모두 남습니다.
  3. 하루 한 번씩 나는 API 502 오류문제: 버스 도착 API가 가끔 502 오류를 내서 화면이 빈 채로 멈췄습니다. 해결: 지수 백오프로 세 번 다시 요청하고, 마지막으로 받은 값을 캐시해 오래된 값이라고 표시했습니다. 결과: 요청이 실패해도 화면이 비지 않습니다.
  4. 탭 키로 선택되지 않는 버튼문제: div로 만든 버튼 때문에 키보드만으로는 페이지를 쓸 수 없었습니다. 해결: button, nav, main 같은 시맨틱 태그로 바꾸고 포커스 표시를 다시 넣었습니다. 결과: 키보드만으로 모든 기능을 쓸 수 있고, Lighthouse 접근성 점수가 68점에서 100점이 됐습니다.
  5. 목록을 내릴 때 밀리는 이미지문제: 이미지가 늦게 뜨면서 아래 내용이 밀렸습니다. 해결: 이미지의 가로세로 비율을 미리 지정해 자리를 잡아 두었습니다. 결과: CLS가 0.21에서 0.01로 줄었습니다.
  6. 1.4MB까지 커진 번들문제: 첫 로딩이 느렸는데, 날짜 라이브러리 전체가 번들에 들어가 있었습니다. 해결: 쓰는 함수만 가져오고 큰 화면은 지연 로딩으로 나눴습니다. 결과: 번들이 1.4MB에서 320KB로, 첫 화면 표시가 2.6초에서 1.1초로 줄었습니다.
  7. 오프라인에서 멈추는 앱문제: 인터넷이 끊기면 흰 화면만 나왔습니다. 해결: 로컬 DB를 먼저 읽고, 네트워크는 데이터를 갱신할 때만 쓰도록 순서를 바꿨습니다. 결과: 비행기 모드에서도 기록을 읽고 쓸 수 있습니다.
