막혔던 것들

프로젝트 상세에도 적어 두었지만, 특히 오래 걸렸던 일곱 가지는 따로 모았습니다. 문제 → 접근 → 결과 순으로 씁니다.

  1. 상태가 일곱 갈래로 흩어짐문제: 견적 조건이 늘 때마다 useState가 하나씩 늘어 일곱 개가 됐고, 하나 바꾸면 다른 게 어긋났습니다.접근: 서로 같이 변하는 값끼리 묶어 useReducer 하나로 합쳤습니다.결과: 조건 추가가 액션 한 줄로 끝나고, 어긋나던 버그가 사라졌습니다.
  2. 두 기기에서 고치면 하나가 사라짐문제: 같은 책 기록을 폰과 노트북에서 고치면 나중 것이 앞의 것을 통째로 덮었습니다.접근: 문서 단위가 아니라 필드 단위로 마지막 수정 시각을 저장해 비교하게 했습니다.결과: 서로 다른 필드를 고친 경우 둘 다 남습니다.
  3. API가 하루 한 번 502문제: 버스 도착 API가 불규칙하게 502를 뱉어 화면이 빈 채로 멈췄습니다.접근: 지수 백오프 재시도 3회와 마지막 성공값 캐시를 넣고, 오래된 값임을 표시했습니다.결과: 실패해도 화면이 비지 않고, 문의가 없어졌습니다.
  4. div로 만든 버튼이 탭으로 안 잡힘문제: 키보드만으로 페이지를 쓸 수 없었습니다.접근: 대부분을 button·nav·main 같은 시맨틱 태그로 되돌리고 포커스 링을 살렸습니다.결과: 키보드만으로 전체 흐름이 가능해졌습니다. Lighthouse 접근성 68 → 100.
  5. 목록을 내리면 이미지가 튐문제: 이미지가 늦게 뜨면서 아래 내용이 밀렸습니다.접근: 가로세로 비율을 미리 지정해 자리를 잡아 두었습니다.결과: CLS 0.21 → 0.01.
  6. 번들이 1.4MB문제: 첫 로딩이 느려 확인해 보니 날짜 라이브러리 전체가 들어가 있었습니다.접근: 쓰는 함수만 가져오고 큰 화면은 지연 로딩으로 잘랐습니다.결과: 1.4MB → 320KB, 첫 화면 2.6s → 1.1s.
  7. 오프라인에서 앱이 죽음문제: 인터넷이 끊기면 흰 화면이 됐습니다.접근: 로컬 DB를 먼저 읽고 네트워크는 갱신용으로만 쓰게 순서를 바꿨습니다.결과: 비행기 모드에서도 기록을 읽고 쓸 수 있습니다.
